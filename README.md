# Территория шин · Мобильная тетрадь

[Открыть работающий прототип](https://ekater5rina-create.github.io/shina-tetrad/). Приложение и репозиторий опубликованы для открытого доступа.

GitHub Actions проверяет расчеты и публикует содержимое `dist` в GitHub Pages после каждого обновления `main`.

При переходе со старого адреса сначала сохраните резервную JSON-копию в разделе «Данные», затем восстановите ее на новом адресе. Браузер хранит записи отдельно для каждого адреса; автоматически они не переносятся.

Учет продаж, шиномонтажа, закупок, расходов и движения кассы. Интерфейс адаптирован для телефона и компьютера в стиле «Территории шин».

## Простая тетрадь

Пять разделов: **Продажи, Закупки, Шиномонтаж, Расход, Возвраты**. Выберите раздел и нажмите «Записать». Введите сумму, способ оплаты и наименование, если оно требуется. Для шиномонтажа название услуги подставляется, время фиксируется автоматически. Артикул, сотрудник, клиент и примечание доступны в необязательных подробностях. Последнее имя сотрудника запоминается на устройстве.

В «Продажи → Записать» доступны 19 вариантов шин из предоставленного владельцем списка. Это ручной каталог, без подключения к МойСклад и без данных об остатках. Поиск по марке, размеру и артикулу; выбор подставляет название, известный артикул и цену за штуку. Сумма = цена × количество, расчет в целых копейках. Цена и итог допускают ручное исправление; последующее изменение количества пересчитает итог по цене за штуку. Повторяющиеся позиции сохранены раздельно с номером строки списка. Служебное слово `code` не считается артикулом. Для отсутствующих товаров есть вариант «Ввести товар вручную». Каталог не создает продажу до нажатия «Сохранить запись».

Раздел «Итого» автоматически собирает записи выбранного дня. Данные прежней версии сохраняются в той же базе браузера.

Кнопка **«Распечатать день»** открывает системное окно печати. Формат A4, книжная ориентация: продажи и возвраты; отдельная страница с закупками, шиномонтажом, расходами, внесениями и итогами наличных. Структура повторяет присланные бумажные бланки. При большом числе записей добавляются страницы продолжения. Печатается весь выбранный день, независимо от текущего раздела или поиска. В системном окне можно выбрать принтер или «Сохранить в PDF»; для чистого бланка выключите колонтитулы браузера.

Кнопка «Отправить в таблицу» — демонстрационная заглушка. Google Таблицы не подключены; при нажатии данные никуда не отправляются.

Мобильное приложение без внешних зависимостей. Локальный запуск: `npm start`, затем http://localhost:4173. Проверки: `npm test`.

## Экран собственника

Кнопка «Собственник» открывает обзор записей этого браузера. Периоды: день тетради, 7 дней, с начала месяца, все записи и свой диапазон. Показатели и выгрузка CSV пересчитываются по одному диапазону; нажатие карточки, полосы или точки открывает исходные записи.

Выручка после возвратов = продажи + услуги − возвраты. Внешние выплаты = закупки + расходы и бонусы + зарплата + возвраты; инкассация исключена. Средняя запись продажи считается по записям типа «Продажа шин», а не по покупателям. Количество шин не включает пакеты и услуги.

Изменение наличных за период — сумма приходов минус выплаты наличными. Остаток — отдельный расчет последнего отмеченного дня: его начало + его наличные движения. Начальные остатки разных дней не суммируются. Расхождения с фактом и отрицательная расчетная касса показываются для проверки.

Пропущенные дни не заменяются нулевой выручкой и не соединяются линией графика. Процент изменения показывается только при полном закрытии всех календарных дней текущего и предыдущего равного периода. При нулевой базе процент не рассчитывается. Прибыль, маржа, остатки склада, планы и прогноз недоступны без дополнительных данных. Экран не создает отдельную авторизацию, общую базу или подключение к МойСклад.

## Правила записей

Сумма записи — общая за указанное количество, не цена единицы. Все расчеты выполняются целыми копейками. Выручка включает продажи шин, пакеты, другие продажи, шиномонтаж, правку и утилизацию. Внесение не является выручкой. Возвраты показываются отдельно. Закупка — выплата, а не расчет себестоимости реализованных товаров; приложение не рассчитывает прибыль и складские остатки.

Остаток наличных = начальный остаток + все поступления наличными − все выплаты наличными. QR, терминал и перевод учитываются отдельно. Смешанная оплата: наличные + один безналичный способ. Для возврата Я.Маркет требуется указать реальный способ выплаты; если возврат не сопровождается выплатой, не вносите его в кассу до уточнения процесса.

Начальный остаток каждого дня подтверждается пользователем. При первом редактировании предлагается факт последнего закрытого дня; автоматически изменения между днями не распространяются. Закрытие требует фактического пересчета денег, сохраняет расхождение, запрещает изменения записей до повторного открытия.

## Хранение

Данные находятся в localStorage конкретного браузера и адреса сайта. Это версия для одного пользователя, без серверной синхронизации и журнала аудита. Очистка браузера удалит записи. Делайте JSON-копии после смены; импорт полностью заменяет базу после подтверждения. CSV выгружает записи выбранного дня для Excel. Снимки тетради не импортировались; стартовая база пустая.

PWA работает без интернета после первого успешного открытия по HTTPS или localhost. На iPhone: меню «Поделиться» → «На экран Домой». При доступе по локальному HTTP-адресу компьютера офлайн-установка может быть недоступна. Для общей работы необходимы серверная база, авторизация, права и журнал изменений.

## Что уточнить перед общей эксплуатацией

Расшифровку сокращений сотрудников и способов оплаты, логику «точка», «перевод/бонус», возвратов Я.Маркет, расчет зарплаты шиномонтажа. В первой версии зарплата и бонусы вводятся как фактические выплаты, проценты не предполагаются.
